# Setting Up Evaluations with Langfuse

## When to Use This Guide
Use this when you have traces but need to set up evaluations to measure quality, identify gaps, or monitor for regressions.

## Evaluation Strategy

### 1. Types of Evaluations

**A. Automated Evaluations (LLM-as-Judge)**
- Reference-free metrics (RAGAS: faithfulness, answer relevancy)
- Reference-based metrics (context recall, answer correctness)
- Custom evaluators (business logic, compliance checks)

**B. Human-in-the-Loop**
- Expert reviews
- User feedback (thumbs up/down)
- Quality assurance sampling

**C. Hybrid Approaches**
- LLM pre-screening → human review
- Confidence thresholds → escalate low-confidence answers

### 2. Evaluation Lifecycle

```
1. Define Metrics
   ↓
2. Collect Ground Truth
   ↓
3. Implement Evaluators
   ↓
4. Run Evaluations
   ↓
5. Analyze Results
   ↓
6. Iterate & Improve
```

**B. Batch evaluation**

def evaluate_batch(dataset: Dataset):
    """Evaluate a batch of examples"""
    results = []

        # Run pipeline
        response = rag_pipeline(example["question"])
        
        # Evaluate
        scores = evaluate_with_ragas(
            example["question"],

            response["contexts"]
        )
        
        # Compare with ground truth

                response["answer"],
                example["expected_answer"]

            "response": response,

    return results

## Best Practices

### Do:
- ✅ Start with 2-3 key metrics (faithfulness, answer relevancy)
- ✅ Use consistent scoring scales (0-1)
- ✅ Include evaluation metadata (timestamp, evaluator version)
- ✅ Sample evaluations for high-volume applications
- ✅ Set up alerts for metric degradation

### Don't:
- ❌ Evaluate every single query (cost/performance)
- ❌ Use different evaluators for the same metric
- ❌ Ignore false positives/negatives in evaluators
- ❌ Forget to update ground truth datasets
- ❌ Over-optimize for metrics at expense of user experience

## Troubleshooting

**Problem**: Evaluations not appearing in Langfuse
**Solution**: 
```python
# Check initialization
langfuse = Langfuse()  # Needs env vars
langfuse.flush()  # Ensure data is sent

# Verify with CLI
npx langfuse-cli api scores list --limit 5
```

**Problem**: LLM-as-judge inconsistent
**Solution**:
- Use same LLM/model for consistency
- Add few-shot examples
- Implement judge calibration
- Use multiple judges + voting

**Problem**: Evaluation too slow
**Solution**:
- Sample evaluations (e.g., 10% of queries)
- Use smaller/faster LLMs for evaluation
- Cache evaluation results
- Run evaluations asynchronously
